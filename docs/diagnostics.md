# Performance captures

Run `octo-manager diagnostics capture --seconds 60 --wait` against the running daemon. Capturing is off by default, lasts 60 seconds unless specified, and accepts integer durations from 1 to 300 seconds. Omit `--wait` to receive the capture ID immediately; use `diagnostics show ID --full` for all retained groups and sampled stacks, or `diagnostics stop ID` to preserve a partial report. Default output includes the ten most frequent query groups without stacks. `--state DIR` selects the daemon as with other commands. Captures do not require a restart, change scheduler policy, or pause work.

Only one capture can run at a time. Supply `--request-id ID` to retry an uncertain start safely: the same ID and duration return the existing capture, while a different duration is rejected. Stopping a terminal capture returns its retained result. Normal shutdown stops recording and saves a partial report; an abrupt restart leaves a descriptor reported as interrupted, without reconstructing missing observations. Failed writes remain explicit and any in-memory report lasts only until another capture or restart. A runtime without the `sqlite.db.query` event rejects capture requests rather than returning a misleading empty report.

Reports live outside SQLite in the state's private `diagnostics/performance/` directory (0700 directories, 0600 files). They are retained until the operator removes them. String, numeric and blob literals, comments and quoted identifiers are redacted before grouping, hashing or persistence. Query shapes and sampled caller stacks still reveal schema and local source paths; keep reports private. The recorder never persists expanded bound values. Quoted identifiers and differing literals can share a shape; unknown token encodings yield an unrecognized shape.

Query counts are completed SQLite statement events for `jobs.sqlite`, including nested internal statements such as `PRAGMA data_version` and `PRAGMA schema_version`. They are not application API call counts. Runtime-reported durations may be zero because of clock precision, exclude unmeasured binding and row-construction work, and overlap for nested statements. Do not sum them as exclusive CPU time. Observer elapsed time measures callback wall time, not all instrumentation cost. Compare uninstrumented CPU separately before claiming an improvement.

Stable scope names identify repository policy, tracking, issues, merging, legacy reconciliation, notification flushing, jobs, digest discovery and digest reconciliation. Async scope duration is wall time; a cycle may include awaited I/O. Only cycles completed during capture are counted, while query totals can include partial cycles. Detached work retains its scope name but cannot alter an already completed cycle's write accounting. A cycle without observed writes excludes ambiguous statements, but neither proves the database was unchanged nor rules out external writes. SQL events from other databases are counted separately and excluded from query groups.

The recorder bounds query groups at 256, scopes at 32, raw SQL at 65536 characters, retained shapes and each sampled stack at 2048 characters, and retained strings at 1 MiB of UTF-16 storage. It samples the first and every hundredth event per group, retaining at most four distinct stacks. Reports expose dropped events, dropped scope starts, dropped stack samples, callback failures and zero-duration counts. On expiry or stop, the subscriber is removed and no further query events are recorded. No per-query timing, stack collection, report allocation or file output runs while capture is disabled.
