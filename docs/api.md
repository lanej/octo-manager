# Local API

The Bun coordinator serves the generated `octomanager.v2` Connect API over its Unix socket. The CLI and Charmed Go dashboard use the generated clients. `GetServerInfo` reports the protocol version; clients check it before requests or dashboard streaming and report incompatible server/client installations clearly. Install the coordinator, CLI, and dashboard together. The v1 service is not served.

RPC records use explicit Protobuf messages, enums, and variants for check/review coverage, feedback, delivery progress and outcomes, merge policy and results, frozen messages and receipts, and archived submissions and policies. Domain records are not serialized inside string or bytes fields, and the API has no `Struct`, `Value`, or `Any` escape hatch. Markdown, logs, and original worker output remain source text. Invalid archived worker results retain their raw source and an explicit invalid-result marker.

Merge operations have dedicated requests and responses. JSON intent files remain local CLI input where appropriate; they are validated and translated into typed requests. CLI JSON output is a presentation format rather than a serialized document nested in an API field. Database JSON serialization remains an internal storage detail.

`bun run generate` exports the domain contract messages, runs Protobuf lint, and regenerates TypeScript and Go bindings. `proto/api-wire-tags.json` preserves field, enum, and variant numbers across property reordering and additive edits; removed tags remain reserved and incompatible type changes require a protocol version change. Generated domain conversion metadata is committed alongside the bindings. Code-generation drift is checked in CI.

Observation variants preserve complete-empty, partial, and unavailable evidence separately. Receipt records preserve exact frozen membership and timestamps; acknowledgment does not accept work, resolve a blocker, or authorize a merge. Diagnostic journal fields have explicit types; unsupported historical fields are identified in `omittedFields`, and the original journal remains stored.

Legacy drafting and publication execution RPCs are retired. Typed historical reads remain available. The scheduler reconciles legacy publishing, enrolling, and uncertain records only when they retain a saved publication brief. It uses the shared GitHub dispatcher, verifies a unique existing marker and the saved head/repository/open state, and enrolls only confirmed matches. Missing or ambiguous matches remain uncertain. Recovery deadlines are persisted before lookup, using delays of one, five, and fifteen minutes, then hourly; longer provider cooldowns still apply. Recovery never invokes a worker or creates a PR.

## Issue lifecycle API

`EnrollIssue` authorizes investigation for a provider-qualified issue in a verified local checkout. `UpdateIssue` records brief-version approvals, publication/follow-up approvals, answers, pause/resume/cancel, and refresh requests. These responses confirm durable decisions, not agent execution or remote effects. `ListIssues` returns twenty summaries per offset page; `GetIssue` returns current state, the latest ten briefs, ten assignments, twenty pending effects, and fifty events. `before_sequence` pages events only. Snapshots include up to fifty issue summaries and latest assignment details for the dashboard.

`IssueStage` and `IssueWaiting` are separate enums. Assignment identity and observations preserve current harness/session/turn information; effect status and URLs retain reconciliation evidence. See [issue state machines](issue-flows.md) for transition prerequisites, current inspection limits, and why Done, terminal agent execution, and tracker closure are different facts.

## Advisory assessments and explicit evidence

`GetAction`, `ListActions` and `ListAgentMessages` return safe projections by default; `full` explicitly exposes untrusted evidence or historical bodies. `GetAssessment` returns typed identity, applicability, state and history, with `full` enabling the exact untrusted input snapshot and model result. Snapshot text is an opaque, potentially truncated LLM-input artifact, not a domain record encoded in a string. `RetryAssessment` requests another bounded attempt on the same applicable failed/interrupted record; it grants no execution or merge authority. See [the security model](security.md).

`GetNotificationMessage` accepts one public message ID for either a grouped dispatch or a single direct delivery. It returns a `NotificationMessage` with typed `items`: actions (feedback or checks), merge entries, issues, submissions, participant updates, references, or explicitly unavailable historical sources. Each frozen member remains represented in order. Producer state, applicability and receipt timestamps are current views; the original membership and rendered delivery remain immutable. Metadata is safe by default; `full` explicitly includes untrusted producer detail and historical bodies.

`AcknowledgeNotificationMessage` records receipt for that exact message and its original members, without accepting or resolving their work. A later arrival creates a new public message ID and cannot be acknowledged by an older ID. Recipient identity and optional exact-body matching remain enforced. Legacy digest inspection/receipt RPCs remain available for administrative clients; they retain their original archived representations.

`ReadNotificationMessage` requires the intended recipient and returns full typed evidence plus separately scoped current operator instructions while recording receipt. Original rendered bodies are omitted. Evidence is explicitly labelled untrusted; reading grants no acceptance, resolution or merge authority. Preparation errors leave receipts unchanged; grouped receipt is atomic. Repeating a read returns the same original members, with current source state, even after a response is lost.

## Runtime activation

The typed API v2 `RuntimeLifecycle` and `octo-manager lifecycle inventory|checkpoint|stop|restore|verify|artifact` report version 1 activation evidence. Installed managed releases identify their immutable package contents and the kernel-mapped environment-provided Bun host; source-mode and unmanaged builds report unknown identity. Readiness comes from the running coordinator socket. A checkpoint binds the inventoried PID/start incarnation to an update UUID, refuses active workers or effects lacking a confirmed native checkpoint, and fences dispatch before draining idle services. It confirms only after those services close; forced worker termination is never invoked by this path. Interrupted or uncertain work is retained in its existing durable owner records and is never replayed by restoration. New releases restore the previous scheduler pause setting. An original drained coordinator cannot reverse that drain and explicitly reports incomplete recovery. Legacy coordinators without the RPC stay intact.

Managed service definitions use restart-after-failure with a startup retirement-policy marker. Unknown policies refuse checkpointing before draining idle work. Native `stop` binds the confirmed checkpoint and fences restoration before acknowledging normal retirement; the installer observes the original PID gone, no manager respawn, and the released owner lock before changing the OS job. Consumed operation UUIDs cannot checkpoint a restored coordinator again.

The shared Bun executable is selected from the service environment and must satisfy `engines.bun`; Octo does not install a private host or change the shared executable permissions. The native identity captures a file descriptor for the kernel-mapped host at startup. Installation freezes the selected bundle and host identity before native retirement, then verifies the new image, readiness, and service-manager PID; a changed shared host produces incomplete activation without another launch. Pending jobs, issue assignments or effects, assessments, recoverable workers, and unresolved merge, repair or submission effects block checkpointing. Every API v2 RPC admission is fenced during native drain except lifecycle inspection and server-version negotiation. Standalone publication retains its independent journal and immutable loaded release; daemon activation does not terminate or replay its operations.
