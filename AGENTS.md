# Development

Use the repository-local [Builder](.agents/skills/builder/SKILL.md), [TypeScript](.agents/skills/typescript/SKILL.md), and [Protobuf](.agents/skills/protobuf/SKILL.md) guidance. Use Node 22+ for the isolated TypeScript quality tools and an environment-provided Bun satisfying the committed package and lockfile. Before handoff, run `PROTOBUF_AGAINST='.git#ref=origin/main' bun run check` to build the application and run the ratcheted TypeScript profile, Bun tests, and strict Protobuf lint, formatting, compilation, and compatibility checks. Keep Markdown paragraphs on one source line.

When adding or moving code, follow [the architecture guide and implementation examples](docs/architecture.md#code-organization) for capability folders, decisions, data access, ports and adapters, and the dashboard’s OpenTUI presentation boundary.

The versioned API lives in `proto/`. Run `bun run generate` after changing it and commit the generated TypeScript bindings. The pinned Buf CLI and TypeScript descriptor rule enforce the Protobuf profile. Keep generated code reproducible and edit generated documentation through the canonical domain metadata or exporter. Use the actual PR base or released schema for compatibility.

The Bun coordinator owns daemon-backed durable state and Git/GitHub effects. The standalone publication CLI owns a separate receipt journal and a short-lived, non-AI publisher; it must not acquire the daemon state lock. Calling agents write PR descriptions, and Octo enforces only basic validity and explicitly declared mechanical format rules. The OpenTUI frontend is an API client and owns its terminal lifecycle. Disconnecting the frontend must not cancel jobs. Workers receive only typed scoped tools. Do not add unrestricted shell tools, load project extensions, copy Codex credentials, or write to remote GitHub objects as part of the demo. Automated tests use synthetic credentials or controlled workers; provider acceptance is separate.

TypeScript quality tools have a separate pinned npm lockfile; install them with `node scripts/check-typescript.mjs tools`. Run `node --max-old-space-size=4096 scripts/check-typescript.mjs lint` for focused feedback. The initial retrofit baseline records existing findings, including dependency declaration incompatibilities; it must never grow. Run `node scripts/check-typescript.mjs ratchet` after fixing old findings and commit the reduction. Generated Protobuf and Codex types are excluded from lint and formatting, but imported declarations still participate in compiler checks.

Record agent work performed outside Octo with `activity record` as described in [the activity guide](docs/activity.md). Use named operations, separate request IDs for attempted/result reports, and one operation ID per execution attempt. Retry reporting with the same request ID after a timeout; do not re-execute the operation to retry its report. Preserve failed and uncertain outcomes and include only observed evidence. Reports do not resolve tracked blockers.
