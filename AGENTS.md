# Development

Use the repository-local [Builder](.agents/skills/builder/SKILL.md), [Go](.agents/skills/go/SKILL.md), and [TypeScript](.agents/skills/typescript/SKILL.md) guidance. Use Node 22+ for the isolated TypeScript tools, Bun 1.4.4, the committed bun.lock, and the Go toolchain declared by go.mod. Run `bun run check` before handoff; it builds both applications, runs the ratcheted TypeScript profile and Bun tests, and runs the portable strict Go profile including race tests and vulnerability analysis. Keep Markdown paragraphs on one source line.

The versioned API lives in `proto/`; run `bun run generate` after changing it and commit both Go and TypeScript bindings. Keep generated code reproducible. Run `bash scripts/check-go.sh fix ./internal/... ./cmd/...` with the declared Go toolchain for scoped mechanical fixes; never weaken lint policy or add a baseline for new code.

The Bun coordinator owns durable state and all Git/GitHub effects. The Charmed Go frontend is an API client and owns its terminal lifecycle. Disconnecting the frontend must not cancel jobs. Workers receive only typed scoped tools. Do not add unrestricted shell tools, load project extensions, copy Codex credentials, or write to remote GitHub objects as part of the demo. Automated tests use synthetic credentials or controlled workers; provider acceptance is separate.

TypeScript quality tools have a separate pinned npm lockfile; install them with `node scripts/check-typescript.mjs tools`. Run `node scripts/check-typescript.mjs lint` for focused feedback. The initial retrofit baseline records existing findings, including dependency declaration incompatibilities; it must never grow. Run `node scripts/check-typescript.mjs ratchet` after fixing old findings and commit the reduction. Generated Protobuf and Codex types are excluded from lint and formatting, but imported declarations still participate in compiler checks.

Record agent work performed outside Octo with `record-activity` as described in [the activity guide](docs/activity.md). Use named operations, separate request IDs for attempted/result reports, and one operation ID per execution attempt. Retry reporting with the same request ID after a timeout; do not re-execute the operation to retry its report. Preserve failed and uncertain outcomes and include only observed evidence. Reports do not resolve tracked blockers.
